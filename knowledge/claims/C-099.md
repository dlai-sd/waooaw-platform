Claim ID:        C-099
Type:            OBLIGATION + ARCHITECTURAL_CONSTRAINT

Statement:       Every WAOOAW agent — internal or customer-facing — must declare
                 a Decision Consequence Map (DCM) in its specification. The DCM
                 classifies every consequential decision type the agent makes into
                 exactly one of two categories:

                 DETERMINISTIC_REQUIRED — the decision is irreversible, financial,
                 constitutional, or carries external commitment (charges a customer,
                 commits to a contract, advances constitutional state, writes to an
                 audit ledger). A wrong or inconsistent output causes harm that
                 cannot be corrected by a subsequent run. These decisions must be
                 verified by an independent process before they are committed.
                 The agent must not self-certify DETERMINISTIC_REQUIRED outcomes.

                 CONSISTENT_SUFFICIENT — the decision produces a reversible,
                 retryable, or advisory output (code generation, content draft,
                 improvement proposal, analysis). A wrong output is caught by the
                 verification loop or escalation protocol and corrected without
                 harm. Consistent LLM output is sufficient; independent
                 deterministic verification is not required.

                 The classification criterion is consequence of error, not
                 complexity of decision. An agent that misclassifies a
                 DETERMINISTIC_REQUIRED decision as CONSISTENT_SUFFICIENT is in
                 violation of this claim and C-002 (Trust through Evidence).

                 Runtime enforcement: at every consequential action, the agent
                 must consult its DCM via CE.ValidateAction before execution.
                 CE.ValidateAction accepts the decision type as a parameter and
                 returns one of:
                   PROCEED_AUTONOMOUS    — decision is CONSISTENT_SUFFICIENT;
                                          agent may act and self-certify output
                   PROCEED_DETERMINISTIC — decision is DETERMINISTIC_REQUIRED;
                                          agent must invoke independent
                                          verification before committing output
                   BLOCKED               — decision type not declared in DCM;
                                          agent must escalate to Founder before
                                          proceeding

                 An agent that proceeds past PROCEED_DETERMINISTIC without
                 completing independent verification is in violation of this
                 claim at runtime. This violation is detectable by CCT-DCM-03
                 (audit log must contain a verification record for every
                 DETERMINISTIC_REQUIRED action committed).

                 DCM as C-070 recursive loop filter: improvements touching
                 DETERMINISTIC_REQUIRED decisions require Founder authorization
                 before the agent's DNA is updated. Improvements touching
                 CONSISTENT_SUFFICIENT decisions may be applied autonomously
                 by the Self-Improvement Analyst. The DCM is the constitutional
                 filter that makes Instinct 2 (improve itself) safe at scale —
                 correct friction where it matters, correct speed where it does not.

                 An agent spec without a DCM is incomplete and cannot pass the
                 AGENT-AUTHORING-GUIDE activation gate.

Reviewer Notes:  WHY DCM AND NOT AN EXTENSION OF DECISION SPACE:

                 Decision Space (existing) answers: what is the agent authorized
                 to do? DCM answers: for each thing it does, what level of trust
                 does the output require before it is committed? These are
                 orthogonal questions. An action can be authorized (Decision
                 Space) but still require independent verification before
                 commitment (DCM). Both are necessary. Neither replaces the other.

                 TWO ENFORCEMENT LAYERS:

                 Authoring time — activation gate checks DCM section present
                 and all decision types classified. An agent spec without DCM
                 cannot be activated. This is the constitutional gate.

                 Runtime — CE.ValidateAction consults DCM before every
                 consequential action. DETERMINISTIC_REQUIRED decisions are
                 routed to independent verification. CONSISTENT_SUFFICIENT
                 decisions proceed autonomously. Undeclared decision types
                 are BLOCKED and escalated to Founder. CCT-DCM-03 audits
                 compliance post-execution.

                 THE FILTER THIS CREATES IN THE C-070 LOOP:

                 Without DCM: Instinct 2 (improve itself) either requires
                 human approval for every improvement (bottleneck) or applies
                 all improvements autonomously (drift risk).

                 With DCM: Instinct 2 reads the DCM. Improvement touches
                 DETERMINISTIC_REQUIRED decision → Founder gate (correct
                 friction). Improvement touches CONSISTENT_SUFFICIENT decision
                 → autonomous (correct speed). Constitutional safeguard and
                 autonomy are no longer in conflict.

                 COMPETITIVE DIFFERENTIATION:

                 No existing autonomous agent platform (Devin, GitHub Copilot
                 Agent, Claude Code, Amazon Q, OpenHands) has a DCM equivalent.
                 All treat verification depth as uniform or as a configuration
                 parameter set by the operator, not as a constitutional obligation
                 derived from consequence of error. WAOOAW's DCM makes the
                 trust-autonomy trade-off a solved architectural problem, not a
                 tuning exercise.
