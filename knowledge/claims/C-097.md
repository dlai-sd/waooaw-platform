Claim ID:        C-097
Type:            OBLIGATION
Statement:       Any sprint task that implements a function performing financial
                 calculation — including but not limited to: price derivation,
                 cost floor computation, margin application, wallet debit/credit,
                 billing amount rounding, and tax calculation — MUST include
                 property-based tests using the hypothesis library in addition to
                 example-based unit tests.

                 Property-based tests MUST cover at minimum:
                 (a) Boundary values: zero input, maximum credible input, identity
                     (zero margin, 100% margin where algebraically defined)
                 (b) Monotonicity invariants: derive_price(cost_floor, m1) ≤
                     derive_price(cost_floor, m2) when m1 ≤ m2 — price rises with
                     margin, never falls
                 (c) Floor enforcement: for any proposed_price < cost_floor output
                     of derive_price, validate_price must return REJECTED
                 (d) Large integer stability: paise values up to 1,000,000 (₹10,000)
                     must not overflow or produce floating-point rounding errors
                     that change the APPROVED/REJECTED outcome

                 Rationale: financial calculations in billing systems are legally
                 binding. An LLM-written test suite of 5 example-based tests covers
                 the happy path but cannot detect: formula inversion bugs (margin
                 applied as markup instead of margin-on-revenue), integer truncation
                 errors, or monotonicity violations at scale. Property-based tests
                 with @given strategies generate hundreds of edge cases automatically
                 and document the mathematical contract as executable code.

                 Enforcement: the Work Contract task scope for any financial
                 calculation task MUST specify hypothesis @given tests. The
                 Constitutional Compliance Test suite (CCT) for that task must
                 include a CCT asserting that hypothesis tests are present in the
                 test file (verifiable by AST inspection of @given decorators).

Confidence:      97%
Source:          IB-009 QA analysis (2026-07-31): derive_price formula
                 floor/(1-margin/100) has three known edge cases where example

                 unchanged; (2) margin approaching 100 causes asymptotic growth —
                 LLM may cap incorrectly; (3) floating-point intermediate
                 calculation truncated to int may flip APPROVED→REJECTED for paise

                 @given(st.integers(min_value=100, max_value=1000000),
                        st.floats(min_value=0, max_value=99.9)) catch all three.
