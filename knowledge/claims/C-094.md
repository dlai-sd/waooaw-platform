Claim ID:        C-094
Type:            OBLIGATION
Statement:       Every WAOOAW agent specification must declare compliance with the current
                 version of the Agent Base Specification (architecture/reference/agents/
                 AGENT-BASE-SPEC.md) by including a `base_spec_version` field in its
                 Platform-Agent Contract (PAC) section. The declared version must equal the
                 current version of the Agent Base Specification at the time of EA review.
                 An agent spec that does not declare `base_spec_version`, declares an outdated
                 version, or fails to implement any MANDATORY section of the Base Spec is
                 constitutionally non-compliant and may not be published to customers regardless
                 of how complete all other spec sections are. When the Agent Base Specification
                 version increments, a compatibility gap scan runs across all existing agent
                 specs. Any agent below the new version receives a P1 spec-gap issue and must
                 be updated before the next agent publication. No waiver, no deadline extension,
                 no "grandfather" clause for existing agents — all agents must track the current
                 base spec version at all times.
Confidence:      100%
Source:          GOAL-004 and EA brainstorming session 2026-07-30. Industry analysis confirmed
                 that the universal failure mode in multi-agent platforms is optional base
                 contracts: LangChain (BaseAgent optional), AutoGen (signal handling optional),
                 CrewAI (degradation handling optional) — all produced agents operating without
                 platform guarantees. WAOOAW's constitutional model requires mandatory
                 inheritance at every layer. C-070 (Constitutional DNA) makes the three instincts
                 mandatory. C-094 extends this mandate to the platform-behavioral layer: how the
                 instincts express themselves in response to platform signals, trial/live mode,
                 graceful degradation, and budget disclosure. Without C-094, agents could pass
                 EA review without any declared behavior for WBE budget signals — and the
                 customer would experience a silent mode change with no disclosure, violating
                 C-049 (Honest Limitation — LAW).
Depends On:      C-070 (Constitutional DNA — mandatory inheritance of three instincts),
                 C-088 (Agent Billing Profile — agent not publishable without billing profile),
                 C-049 (Honest Limitation — BUCKET_EMPTY disclosure is a C-049 enforcement),
                 ADR-035 (PAC Standard — defines the format and validation rules)
Produces:        AGENT-AUTHORING-GUIDE §PAC (mandatory gate section for every new agent);
                 AGENT-BASE-SPEC.md version field (current required version);
                 Activation Gate Section 11 PAC checklist (6 items);
                 CONSTITUTIONAL_DNA.md Base Spec Compliance section;
                 Gap Scanner (scripts/gap_scanner.py) — detects agents below current base spec;
                 P1 spec-gap issues raised automatically when base spec version bumps
Contradicted By: NONE — no domain specialization, urgency, or business pressure may override
                 the base spec compliance gate. An agent that passes all domain-specific
                 simulation scenarios but lacks a PAC section is not a complete WAOOAW agent.
Status:          RATIFIED — 2026-07-30 (Founder: Yogesh Khandge — EA session 2026-07-30)
Reviewer Notes:  The Agent Base Specification is intentionally a DOCUMENT (not code) to ensure
                 that non-technical stewards (Ojal — Ethics Officer, Sujay — Business Growth)
                 can review and understand what every agent inherits. Code-based base classes
                 (LangChain, AutoGen) hide the base behavior in source code that only engineers
                 can read. WAOOAW's document-based base spec is readable by all three stewards,
                 auditable by the Constitutional Analyst, and independently versioned without
                 requiring code changes.

                 The PAC YAML section inside each agent spec serves double duty:
                 1. Human-readable declaration for Ojal/Sujay to understand agent behavior
                 2. Machine-parseable for the Gap Scanner and Activation Gate validator

                 The base spec's customer-vocabulary requirement (budget signals must use
                 the agent's domain terms, not platform terms) is itself a constitutional
                 extension of C-042 (Vocabulary Mandate) applied to platform communication.
                 A dental marketing agent that tells Dr. Mehta his "LLM bucket is at 85%"
                 is in violation of both C-042 and C-049.
