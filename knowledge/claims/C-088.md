Claim ID:        C-088
Type:            OBLIGATION
Statement:       No WAOOAW agent may be offered to any customer — in trial, demo, or live
                 mode — without a Founder-authorized Agent Billing Profile on record in the
                 platform's billing registry. The Agent Billing Profile must specify: all
                 threads the agent consumes (platform and agent-specific), default bundle
                 rations for each offering tier (Starter/Runner/Winner or equivalent),
                 minimum wallet requirements per active skill, trial-mode substitutions
                 (zero-cost thread mappings), and constitutional billing obligations specific
                 to this agent's domain. An agent specification approved by the Enterprise
                 Architect is NOT publishable until its Billing Profile is separately
                 Founder-authorized. The two authorizations are independent gates. Billing
                 authorization may not be delegated below Founder level.
Confidence:      100%
Source:          GOAL-004 brainstorming session 2026-07-30. Operational Scenario S-11: adding
                 a new agent (e.g. Restaurant Operations Agent) requires zero code change to
                 the billing engine — only a completed Billing Profile fed to the agent-agnostic
                 WBE. Without this claim, an EA-approved agent could be offered to customers
                 with no defined cost floor, no bundle allocations, and no prepaid gate for
                 its threads. The platform could serve customers at an undefined — potentially
                 negative — margin. C-088 closes this gap by making the Billing Profile a
                 mandatory publication gate, independent of the agent specification gate.
Depends On:      C-089 (Minimum Margin Floor — enforced via the Profile's cost derivation),
                 C-091 (Thread Catalog Sovereignty — Profile references Thread Catalog entries),
                 C-051 (Resource Transparency — customer must know what they are getting; the
                 Profile defines the bundle), C-036 (Skills declared — Billing Profile extends
                 this obligation to cost attribution per skill)
Produces:        institutional.billing_profiles table row (one per agent type, status =
                 FOUNDER_AUTHORIZED required); WBE refuses to serve any agent without a
                 FOUNDER_AUTHORIZED billing_profiles entry; CI gate: new agent spec PR without
                 a referenced billing_profiles entry is flagged GATE_BLOCKER; directory
                 architecture/reference/billing/billing-profiles/ containing one profile
                 document per agent type.
Contradicted By: NONE — no business convenience, speed pressure, or prior agent specification
                 approval may override the requirement. An EA-approved agent without a Billing
                 Profile is constitutionally not yet a product.
Status:          RATIFIED — 2026-07-30 (Founder: Yogesh Khandge — GOAL-004 spec phase)
Reviewer Notes:  This claim deliberately separates agent-specification approval (EA gate) from
                 billing authorization (Founder gate). EA approves what the agent CAN DO.
                 Founder authorizes what the agent COSTS and at what margin. These are different
                 decisions requiring different authority levels.

                 Retroactive application: DMA, Trading, Agricultural Advisor, and Private Tutor
                 receive a one-sprint grace period (GOAL-004 D-09) to produce their Billing
                 Profiles. After D-09, all four agents are compliant. Any agent added after
                 GOAL-004 completes must have its Billing Profile authorized before EA approval
                 is declared final.

                 The trial-mode substitution requirement is essential: customers must be able
                 to experience an agent at zero cost before committing. The Billing Profile
                 defines exactly which threads are substituted in trial mode so the trial
                 experience is architecturally predictable — not ad-hoc per-agent improvisation.

Simulation:      SIM-BILLING-01 (added to simulation/ in GOAL-004 sprint): New agent
                 (Restaurant Operations) added to MCP registry without a Billing Profile →
                 WBE rejects all service requests for this agent with error BILLING_PROFILE_
                 MISSING → Platform Operations agent raises Founder Action → Billing Profile
                 created → Founder authorizes → WBE accepts → agent served. Test: 3/3 PASS.
