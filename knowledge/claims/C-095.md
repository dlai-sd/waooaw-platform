Claim ID:        C-095
Type:            OBLIGATION
Statement:       Every new WAOOAW platform service or software component must have a
                 Founder-authorized Component Manifest (architecture/reference/components/
                 manifest/{component-id}.yaml per ADR-035) AND a compiled EA-produced Code
                 Skeleton (src/{service}/skeleton/ directory) before any implementation
                 sprint fires. The task_decomposer.py pre-flight gate enforces this
                 computationally: any Work Contract task with task_type=IMPLEMENTATION
                 that references a service without a compiled skeleton is blocked with
                 SkeletonMissingError and cannot proceed. This is not a process recommendation
                 — it is a computational gate. No exception, no bypass, no "skeleton will
                 be added later." The manifest and skeleton ARE the entry door to code.
                 Retroactive application: existing services (CE, BP, PR, AIR) receive
                 their manifests and skeletons in GOAL-PLATFORM-REGISTRY as their first
                 constitutionally compliant documentation. Future services require manifests
                 and skeletons BEFORE implementation begins.
Confidence:      100%
Source:          SIM-PLATFORM-001 (30/30 PASS, 2026-07-30). Simulation validated: without
                 skeletons, the LLM invents class names and method signatures, causing
                 CS0246/CS1061 build failures requiring 2-3 retries. With skeletons, the
                 PTR is populated before Sprint Day 0, type invention is structurally
                 impossible, first-attempt compile rate approaches 100%. The 75% token
                 reduction and 67% attempt reduction are simulation-validated.
                 Constitutional basis: C-059 (Implementation Traceability — code must trace
                 to spec) is strengthened by this claim. The manifest IS the spec in
                 machine-readable form. The skeleton IS the spec expressed in the target
                 programming language. Together they make C-059 traceability automatic:
                 every src/ file's # Implements: header points to the manifest section
                 that the skeleton formalized.
Depends On:      C-059 (Implementation Traceability — skeleton carries # Implements: headers),
                 C-088 (Agent Billing Profile — same gate pattern: component unpublishable
                 without billing profile; this claim applies the same gate to implementation),
                 ADR-035 (Platform-Agent Contract Standard — manifest format),
                 ADR-036 (EA Skeleton Standard — what skeletons contain)
Produces:        task_decomposer.py SkeletonMissingError gate (pre-flight check);
                 ADR-036 (EA Skeleton Standard — what a skeleton must contain and how EA
                 produces it); architecture/reference/components/manifest/ directory
                 (one YAML per service); src/{service}/skeleton/ directories;
                 platform-component-registry.yaml (lists all components with manifest paths);
                 scripts/blueprint_assurance.py (validates runtime conformance to blueprints);
                 GOAL-PLATFORM-REGISTRY execution plan (delivers this claim and its artifacts)
Contradicted By: NONE — urgency, sprint deadline pressure, "we'll add the manifest after"
                 convenience, and "the spec is in prose form" justifications do not override
                 this gate. The gate exists precisely because these pressures existed before
                 it did: WC-012 through WC-015 were built without manifests and required
                 retroactive documentation. This claim prevents that pattern from repeating.
Status:          RATIFIED — 2026-07-30 (Founder: Yogesh Khandge — GOAL-PLATFORM-REGISTRY
                 specification session)
Reviewer Notes:  The EA Skeleton Standard (ADR-036) defines the hard boundary between what
                 EA produces (type contracts: interfaces, data models, exceptions, router stubs
                 with NO business logic) and what implementation sprints produce (method
                 bodies that fulfill the contracts). This boundary is constitutional because
                 it enforces separation of concerns at the institutional level:
                 - EA (INST-004) exercises architectural judgment: what the service IS
                 - Platform IT Expert (INST-010) exercises implementation skill: how it WORKS
                 These are different decisions at different responsibility levels.
                 Mixing them in one sprint produces the type-invention failures that
                 the simulation measured.

                 Note on EA authority to produce skeleton files: BOOTSTRAP originally
                 prohibits EA from writing src/ code. ADR-036 clarifies that skeleton files
                 are spec artifacts expressed in the target language — not business logic.
                 Analogy: an architect draws a load-bearing wall in a blueprint. That drawing
                 is not "construction" — it is the specification that construction must follow.
                 EA producing IWalletService with method signatures is the blueprint drawing.
                 Platform IT Expert writing the SQL and Redis logic is the construction.
                 ADR-036 makes this distinction constitutional and permanent.

                 The 15-day Blueprint Assurance Run (scripts/blueprint_assurance.py) is the
                 ongoing validation that the running system continues to match its blueprints.
                 C-095 establishes the gate at build time. The Assurance Run validates at
                 run time. Together they close the loop: blueprint → code → runtime →
                 blueprint (continuous validation).

Simulation:      SIM-PLATFORM-001 (2026-07-30): 30/30 PASS. Track A (no skeleton):
                 3 LLM attempts, 24,000 tokens, 2 build errors per task. Track B
                 (with skeleton): 1 LLM attempt, 6,000 tokens, 0 build errors.
                 75% token reduction. 100% first-attempt compile improvement.
                 Preserved activities: 10/10 (PR review, merge, CI/CD, CCT gate all
                 unchanged or enhanced). File: simulation/sim_platform_001_manifest_
