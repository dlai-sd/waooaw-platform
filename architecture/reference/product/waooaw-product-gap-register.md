## Gap Intake Rule

Focused grooming may add a shared gap only when the gap:

1. Is required by more than one professional or is invariant to professional type.
2. Cannot be satisfied by an existing Agent Base Spec or PAC obligation.
3. Names the earliest customer-outcome epic affected.
4. Names the evidence that will prove closure.
5. Does not duplicate a professional-domain gap.

## Focused Grooming Protocol for Shared Gaps

The first concern named in `Grooming owner` is the grooming lead until the Product Owner assigns an authorized office. Grooming must add the following fields before a gap can enter a Work Contract:

| Required field | Grooming output |
|---|---|
| Customer scenario | Actor, context, trigger, desired outcome, and customer vocabulary |
| Acceptance criteria | Observable happy path, boundary cases, and failure/degradation behavior |
| Evidence method | Customer proof, conformance test, CCT, operational evidence, or an explicit combination |
| Closure metric | Quantified threshold or deterministic pass/fail condition |
| Contract trace | AEEC clause, Agent Base Spec section, PAC signal, or explicit non-applicability |
| Delivery ownership | Authorized office and consuming epic/story |
| Dependencies and risks | Legal, domain, provider, data, security, operational, and Founder-action prerequisites |

A gap remains `UNGROOMED` until all fields are present. Grooming does not authorize implementation; the resulting work still requires an approved Work Contract and applicable session authorization.

## Program Gate Views

### Before Wave 1 Implementation

PG-02, PG-03, PG-04, PG-07, PG-08, PG-10, and PG-11 must be closed at specification level. Their implementation closes through the earliest Wave 1 stories that exercise them.

### Before Each Epic Closes

Every `WAVE_BLOCKER` whose `Earliest wave` equals or precedes that epic must be either:

- `CLOSED` with linked customer or conformance evidence, or
- explicitly reclassified through an approved architecture decision explaining why it no longer blocks the outcome.

`UNGROOMED`, `DEFERRED`, or repository implementation evidence without the required customer proof cannot satisfy an epic exit gate.
